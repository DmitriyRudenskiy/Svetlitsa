Порядок внутри майлстоуна фиксирован стрелкой критического пути `docs/roadmap.md` раздел 3:
`svetlitsa-efl → svetlitsa-ui → izba/traktir/bukvar`. Каждая задача = одна итерация по ТЗ 5
(оригинал → парити-лист → логика + тесты → UI → smoke + скриншот → журнал). Бюджет майлстоуна —
L (≤ 20 итераций, ТЗ 6.8), после калибровки М0 число пересчитывается.

## 1. `svetlitsa-efl` — FFI к EFL (первые итерации, риск «не заведётся»)

- [ ] 1.1 `sys`-слой: `bindgen` по заголовкам `/opt/svetlitsa-efl` (Eina, Eo, Evas, Ecore,
      Ecore_Wl2, Eet, Efreet, Edje, Elementary), генерация через `xtask`, каталог `include/`
      зафиксирован списком заголовков.
- [ ] 1.2 Проверка гипотезы FFI на живом объекте: создать/уничтожить `Eo`-объект из Rust,
      Eo-колбэк в главном потоке (ТЗ 4.3), утечек нет (проверка счётчиком ссылок/`eina`-магикой).
- [ ] 1.3 `safe`-слой: ссылки, время жизни, `Drop`, ошибки; ни одного `unsafe` вне границ (ворота).
- [ ] 1.4 Загрузчики и модули: открыть изображение через `evas`-загрузчик, проверить, что `dlopen`
      сработал на динамической musl (продолжение задачи 2.4 `musl-only-libc`).
- [ ] 1.5 Парити-лист крейта: перечень покрываемых API EFL, вердикты «нужно/не нужно 1.0».
