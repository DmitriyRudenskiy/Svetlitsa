## Why

М1 «Фундамент» (ТЗ 8) — первый майлстоун, после которого появляется смысл говорить о программах:
без FFI-слоя к EFL, минимального UI-набора, хранилища настроек, модели меню и модели раскладок
ни один из 28 последующих артефактов не написать. Сейчас у 38 из 39 крейтов в `src/` одна строка
документирующего комментария, `main.rs` нет ни у одного.

М1 выбран моментом, когда надо заложить то, что потом переделывать дорого:

- **FFI.** Пока привязки не написаны, неизвестно, переживает ли связка «Rust + динамическая musl +
  EFL с `dlopen`-модулями» загрузку загрузчиков и им-модулей. Это надо узнать до того, как под
  `svetlitsa-ui` появятся десятки вызовов.
- **Строки под i18n.** Если М3–М4 писать без `gettext`-макросов, все файлы придётся перечеркивать
  (ТЗ 3.7, `po/` пуст).
- **Локаль не из libc.** musl не даёт ни данных локалей, ни полного `iconv` (ADR-0023): имена
  месяцев, сортировка, перекодировки — собственная реализация. Первые потребители (`лавка` в М2,
  `beresta` в М3) наступят на это сразу, обёртка нужна в М1.
- **Тема и иконки.** Ворота 10.3 красят «серую тему» механически: без токенов темы не проходит ни
  один скриншот-контур, а `xtask icons --check` требует закрытого списка имён (ADR-0012).

## What Changes

- `svetlitsa-efl` — два слоя по ТЗ 3.2: `sys` (тонкие обёртки, `bindgen` по заголовкам из
  `/opt/svetlitsa-efl`) и `safe` (типизированный API, EO-объекты, ссылки, потоки).
- `svetlitsa-ui` — минимум по таблице 4.4: окно, кнопка, entry, box/table, меню, диалог,
  StatusStrip; всё на Elementary, всё с темой «Лубок» через Edje.
- `svetlitsa-config` — keyfile-совместимое хранилище (читает `~/.config`-файлы MATE-формата),
  без dconf (в Alpine его нет, и он тянет GSettings/D-Bus-слой).
- `izba` v1 — «О программе», миниатюры по XDG-спеке, хелперы вывода/мониторов через протоколы сеанса.
- `traktir` v1 — чтение `.menu` через Efreet-FFI в собственные структуры + тесты на дампах (М0).
- `bukvar` v1 — модель раскладок/опций на `xkbcommon`-крейте; применение — на стороне композитора (М2).
- Новые сквозные вещи: `locale-services` (месяцы/дни недели/сортировка/перекодировки на Rust),
  `theme-and-icons` (токены «Лубка», закрытый список иконок), `i18n`-каркас (`po/<бинарь>.po`).

## Capabilities

### New Capabilities

- `efl-ffi-bindings` — слои `sys`/`safe`, генерация привязок, правила безопасности FFI,
  совместимость с динамической musl и `dlopen`.
- `ui-toolkit-surface` — минимальный набор виджетов и правил UI (таблица 4.4), тема, скриншотные
  контуры.
- `desktop-foundation` — настройки, модель меню, модель раскладок, локаль вне libc, тема и иконки,
  i18n-каркас: то, чем пользуются все последующие компоненты.

### Modified Capabilities

- `control-point-window` (change `m0-control-point`) — `svetlitsa-ui` из контрольной точки
  доращивается до минимума 4.4, контракт demo-клиента не меняется.

## Impact

- **Код:** `crates/svetlitsa-efl`, `svetlitsa-ui`, `svetlitsa-config`, `izba`, `traktir`, `bukvar`,
  новый крейт локализации; `xtask` — шаг генерации привязок и проверка, что `sys`-слой не
  содержит ручных правок.
- **Оценка:** L по ТЗ 6.8 (≤ 20 итераций) на весь майлстоун; после калибровки М0 число становится
  фактом и переносится в `docs/roadmap.md`.
- **Ворота:** с появлением кода красятся `parity` (нужны зеркала М0), `icons --check` и `licenses`;
  это ожидаемое поведение, а не регресс (ТЗ 6.3).
- **Не входит:** применение раскладок (М2, композитор), панель, композитор, порталы.
