## ADDED Requirements

### Requirement: Файловые операции идут через VFS-границу и не блокируют интерфейс

`ambar` SHALL выполнять файловые операции через `svetlitsa-vfs` (GIO-FFI: файлы, корзина,
монтирование, GVFS-монты), каждая длительная операция SHALL быть фоновой задачей с прогрессом в UI;
модель папок — инкрементальное сканирование с `inotify`. Прямых вызовов `std::fs` в обход границы
в компонентах быть не должно (ТЗ 9.17).

#### Scenario: Копирование 1000 файлов остаётся отзывчивым

- **WHEN** smoke-сценарий копирует 1000 файлов
- **THEN** прогресс отражается в UI, окно отвечает (проверка кликом/привязкой во время операции),
  отмена операции завершает её без «половины скопированного»
- **AND** замер лежит в `artifacts/` с digest образа ворот

#### Scenario: Ошибки прав и симлинков — часть контракта

- **WHEN** операция упирается в права, висячий симлинк или чужую владельца-галочку
- **THEN** пользователь получает конкретную ошибку, а не «не удалось»; поведение каждой позиции
  перечня 9.17 зафиксировано в парити-листе

### Requirement: Интеграция с остальными программами — контракты, а не запускаемые командные строки

`ambar` SHALL открывать файлы через mime-действия (`svetlitsa-xdg` + Efreet), показывать миниатюры
через `izba`, вызывать `uzelok`/`beresta`/`morzyanka`/`vernissage` именованными D-Bus-контрактами;
рабочий стол (десктоп-иконки) SHALL жить в отдельном процессе `ambar-desktop`.

#### Scenario: Открытие «в нужной программе» без угадывания

- **WHEN** пользователь открывает `.txt`, `.png`, `.cbz`, архив
- **THEN** открываются `beresta`, `vernissage`, `svitok`/`uzelok` соответственно — по реестру mime,
  а не по расширению в `match`
- **AND** отсутствие приложения даёт внятную ошибку с предложением выбрать приложение

#### Scenario: Расширение не роняет амбар

- **WHEN** расширение `pristroyki` падает в процессе работы
- **THEN** `ambar` остаётся работоспособным (MVP по 9.30: расширение — отдельный процесс),
  а падение попадает в журнал сеанса

### Requirement: Десктоп-иконки и панель не воюют за слой

`ambar-desktop` SHALL занимать слой обоев/иконок через `wlr-layer-shell` (или эквивалентный
договор с композитором) и не перекрывать панель `lavka` и окна; порядок слоёв фиксируется
скриншот-проверкой.

#### Scenario: Три слоя на одном экране

- **WHEN** включены обои, десктоп-иконки, панель и открыто окно
- **THEN** снимок композитора показывает именно такой порядок, а smoke-проверка координат
  подтверждает, что панель не залезла на окно и наоборот
