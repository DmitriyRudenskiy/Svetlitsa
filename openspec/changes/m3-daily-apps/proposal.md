## Why

М3 «Кровля» (ТЗ 8) — первый майлстоун, результат которого видит пользователь: восемь программ
повседневного цикла (ТЗ 9.9–9.16) плюс «Памятка» (9.31). Он же первый, где проверяется
**полезность** системы, а не её сборка: DoD — «открыть текст → посчитать → снять скриншот».

Отдельным change он нужен по трём причинам:

1. **Зависимости определились в М1–М2 и сами не появятся.** `morzyanka` — `vte`-парсер + pty +
   `zwlr-data-control` для копипаста; `gramofon` — `pipewire-rs` (ADR-0022, v1 сразу PipeWire);
   `dagerotip` — собственный путь захвата `starshina` (М2, итерация б); `beresta` — `encoding_rs`
   и таблицы локали (М1); `vernissage` — миниатюры `izba` и смену фона через `domovoy`.
2. **MVP-сценарий важнее списка фич.** По ТЗ 6.9 программа не готова, пока не закрыт её MVP из
   перечня 9.x; по 9.30 часть MVP сознательно уже оригинала (у `beresta` — один документ без
   вкладок и поиск без регулярных выражений). Без зафиксированного MVP восемь программ
   превращаются в восемь недоделанных.
3. **Порядок внутри майлстоуна — часть плана.** Первыми идут те, где риск не в объёме, а в
   неизвестном: `morzyanka` (производительность терминала, escape-последовательности) и `gramofon`
   (тонкое поведение PipeWire, mock ничего не проверяет).

## What Changes

- `beresta` (9.9, M) — редактор: вкладки Naviframe, поиск/замена, undo/redo, кодировки
  (`encoding_rs`), подсветка на своём рендере, плагины `BerestaPlugin` в-процессе.
- `schoty` (9.10, S) — калькулятор: парсер на `nom`, basic/научный, история, тест-таблица 50+ выражений.
- `morzyanka` (9.11, M) — терминал: `Evas_Textgrid` + парсер-крейт `vte`, pty, вкладки, профили
  в `svetlitsa-config` с миграцией `/org/mate/terminal/`, копипаст через `zwlr-data-control`.
- `dozor` (9.12, M) — монитор: `sysinfo` как источник метрик (MVP по 9.30), свой виджет Plot,
  дерево процессов, kill/stop/continue с подтверждением.
- `vernissage` (9.13, S) — просмотр изображений: Evas-загрузчики + `image`, EXIF, поворот JPEG без
  потерь, слайд-шоу, «установить как фон» → `domovoy`.
- `uzelok` (9.14, M) — архиватор: ядро с trait `Archive` (tar/gz/bz2/xz/zst/zip с паролем;
  7z/rar — чтение), UI поверх CLI-ядра, интеграция с `ambar` (М4).
- `gramofon` (9.15, S) — микшер PipeWire: устройства, уровни по приложениям, mute; привязка
  (нативный `libpipewire` или сокет `pipewire-pulse`) фиксируется ADR **до первой строки**
  (ADR-0022, вторая привязка запрещена воротами).
- `shkatulka` (9.16, M, М3–М4) — три бинаря: `dagerotip` (снимок), `syschik` (поиск файлов),
  `letopis` (журналы сеанса, JSONL).
- `pamyatka` (9.31, S) — вне MATE: менеджер буфера обмена (история, закреплённые, вызов по
  глобальной привязке `starshina`), модель поведения — по `parcellite`, транспорт —
  `zwlr-data-control` (ADR-0021).

## Capabilities

### New Capabilities

- `daily-apps` — восемь программ: MVP-сценарий каждой, зависимость от платформенных границ,
  запрет на «свой огород» вместо `svetlitsa-ui`/`izba`/`traktir`.
- `screen-capture` — единый путь захвата экрана/окна: композитор как единственный источник кадра
  для `dagerotip`, smoke-скриптов и будущего портала `Screenshot` (М5).

### Modified Capabilities

- `session-smoke` (change `m2-session-frame`) — сценарий «открыть текст → посчитать → снять
  скриншот» строится на `svetlitsa-input` и захвате композитора, а не на отдельной тестовой обвязке.

## Impact

- **Код:** восемь (с `pamyatka` — девять) новых бинарей поверх `svetlitsa-ui`/`izba`/`traktir`;
  новые зависимости только из уже выбранного списка (`vte`, `nom`, `sysinfo`, `zip`, `tar`,
  `kamadak-exif`, `pipewire-rs`, `encoding_rs`); медиапроигрывателя в 1.0 нет — `gstreamer` в
  графе не появляется (проверено по ТЗ 9: ни одна программа его не требует).
- **Оценка майлстоуна:** L (≤ 20 итераций) по ТЗ 6.8; после калибровки М0/М2 пересчитывается —
  именно майлстоуны программ исторически дают наибольший перелёт.
- **Риск:** «восьмая программа» — соблазн сделать один универсальный редактор вместо восьми
  разных сущностей; лечится парити-листом на каждую (ТЗ 6.9).
- **Не входит:** `ambar` (М4), апплеты (М4), миграция настроек (М4), порталы (М5).
