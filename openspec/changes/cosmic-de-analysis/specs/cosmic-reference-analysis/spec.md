## ADDED Requirements

### Requirement: Каталог-аналиторий `idea/`

Система SHALL хранить зеркала внешних репозиториев в каталоге `idea/` корня проекта, и этот
каталог SHALL быть перечислен в `.gitignore`. В git не SHALL попадать ни одно зеркало, ни один
`target/` внутри него.

#### Scenario: Зеркало не попадает в git

- **WHEN** в `idea/` склонирован хотя бы один репозиторий
- **THEN** `git status --short` не содержит путей, начинающихся с `idea/`
- **AND** в `.gitignore` есть строка `idea/`

### Requirement: Ограниченный состав зеркал

Разбор SHALL зеркалировать только подмножество репозиториев, названное графом зависимостей
`fsvm88/cosmic-overlay`: 30 подмодулей `pop-os/cosmic-epoch`, `libcosmic`, `iced`, `cosmic-text`,
`cosmic-protocols`, `pop-launcher`, `xdg-desktop-portal-cosmic` и мелкие переиспользуемые крейты
pop-os без GUI. Клонировать весь орг `pop-os` (300 репозиториев, 12.45 ГБ) SHALL НЕ.

#### Scenario: Тяжёлые не-COSMIC репозитории не клонируются

- **WHEN** разбор завершён
- **THEN** в `idea/` нет каталогов `linux`, `linux-firmware`, `mesa`, `virtualbox`, `wallpapers`,
  `gtk4`, `systemd`
- **AND** суммарный объём `idea/` не превышает 3 ГиБ (`du -sh idea`)

#### Scenario: Клон лёгкий

- **WHEN** репозиторий кладётся в `idea/`
- **THEN** он клонирован `--depth 1 --single-branch --no-tags`
- **AND** у него нет каталога `target/` (сборка зеркал не запускается)

### Requirement: Поэтапность: один репозиторий — один завершённый шаг

Разбор SHALL идти по одному репозиторию: клон → вердикт в реестр → коммит → следующий репозиторий.
Коммит SHALL быть единицей прогресса, и шаг SHALL НЕ считаться завершённым, пока вердикт репозитория
не записан в реестр.

#### Scenario: Шаг закрыт

- **WHEN** репозиторий разобран
- **THEN** в `git log -1 --stat` есть правка `docs/analysis/cosmic/reestr.md`
- **AND** в реестре есть ровно одна строка с именем этого репозитория

#### Scenario: Пачка без вердиктов не коммитится

- **WHEN** склонировано несколько репозиториев, но ни по одному нет вердикта
- **THEN** коммит не создаётся

### Requirement: Реестр разбора

Разбор SHALL вести единственный документ-реестр `docs/analysis/cosmic/reestr.md`. Строка реестра
SHALL содержать: имя репозитория, лицензию, размер зеркала, назначение в одну строку, вердикт и
наш затронутый крейт (или `—`). Отдельные отчёты на репозиторий SHALL НЕ создаваться.

#### Scenario: Строка полная

- **WHEN** в реестр добавлена строка по разобранному репозиторию
- **THEN** заполнены все шесть полей, включая `—` там, где крейт не затронут
- **AND** в `docs/analysis/cosmic/` не появилось файла с именем репозитория

### Requirement: Закрытый список вердиктов

Вердикт SHALL быть ровно одним из: `переносим` (берём идею или контракт в наш код), `добавляем`
(берём как готовую зависимость), `не переносим` (конфликтует со стеком или ADR), `мимо` (к Светлице
не относится). Вердикт SHALL сопровождаться уровнем: `контракт`, `крейт`, `содержимое` или `—`.

#### Scenario: Вердикт аргументирован

- **WHEN** строке присвоен вердикт `переносим` или `добавляем`
- **THEN** в строке указан уровень и назван наш крейт
- **AND** для `добавляем` указана лицензия, совместимая с ADR-0002

#### Scenario: Конфликт со стеком помечен

- **WHEN** репозиторий завязан на `iced`/`wgpu`/`smithay` как на GUI или композитор
- **THEN** вердикт `не переносим` и в пометке назван ADR-0004 (GUI-основа) или ADR-0007

### Requirement: Список пакетов для сборки DE

Документ `docs/analysis/cosmic/pakety.md` SHALL перечислять пакеты, нужные для сборки COSMIC DE,
слоями (тулчейн / GUI / мультимедиа / система / точечные), в двух колонках: Gentoo-атом из оверлея
и Debian/Ubuntu-эквивалент. Источник атомов SHALL быть указан (ebclass или ebuild), а имена пакетов,
не подтверждённые чтением оверлея, SHALL быть помечены как предположение.

#### Scenario: Источник назван

- **WHEN** слой списка прочитан
- **THEN** для него назван файл-источник (`eclass/cosmic-common.eclass` либо конкретный ebuild)
- **AND** ни один атом не приведён без Debian-колонки или явной пометки «не проверялось»

#### Scenario: Версии тулчейна взяты из оверлея

- **WHEN** в списке указан rust или LLVM
- **THEN** версия совпадает со значением из `eclass` (`RUST_MIN_VER`, `LLVM_COMPAT`), а не из памяти

### Requirement: Сравнение компонентов

Документ `docs/analysis/cosmic/sravnenie.md` SHALL сопоставить все 28 компонентов Светлицы из карты
ТЗ 2 с космическими эквивалентами; отсутствующий эквивалент SHALL быть помечен `—`, а не пропущен.
Документ SHALL содержать итоговый вывод о том, переносим ли стек целиком.

#### Scenario: Покрытие полное

- **WHEN** сравнение готово
- **THEN** в нём 28 строк по числу компонентов карты ТЗ 2
- **AND** каждая строка имеет вердикт из закрытого списка

#### Scenario: Вывод о стеке есть

- **WHEN** сравнение готово
- **THEN** в документе есть отдельный абзац-вердикт о переносимости стека с опорой на ADR-0004
  (GUI-основа) и ADR-0007 (композитор)

### Requirement: Граница разбора

Разбор SHALL НЕ менять код крейтов, `Cargo.toml`, `Cargo.lock` и ворота `xtask ci`. Любой вердикт
`добавляем` SHALL оставаться рекомендацией до отдельной задачи с проверкой лицензии.

#### Scenario: Код не задет

- **WHEN** любой коммит разбора
- **THEN** `git show --stat` не содержит `crates/`, `Cargo.toml`, `Cargo.lock`, `xtask/`

### Requirement: Находки разбора имеют адрес в контракте проекта

Каждая находка, меняющая контракт Светлицы, SHALL быть перенесена в документ контракта (`TASK.md`,
`docs/adr/`, `docs/parity/`) со ссылкой на строку реестра, а не оставаться внутри
`docs/analysis/cosmic/`. Перенос SHALL не касаться кода: `crates/`, `Cargo.toml`, `Cargo.lock`,
`xtask/` остаются нетронутыми.

#### Scenario: Порталы закрыты в ТЗ

- **WHEN** перенос выполнен
- **THEN** в ТЗ (М5 и 9.28) есть требование к бэкенду порталов freedesktop как части объёма М5
- **AND** в нём есть ссылка на строку `xdg-desktop-portal-cosmic` реестра

#### Scenario: У компонента без внешнего референса это видно из его парити-листа

- **WHEN** разбор не нашёл космического эквивалента компоненту
- **THEN** в его парити-листе есть строка «Внешний референс (COSMIC): отсутствует» с перечнем
  проверенных списков и номером строки сравнения

#### Scenario: Кандидаты не стали зависимостями

- **WHEN** перенос выполнен
- **THEN** `Cargo.toml` и `Cargo.lock` не изменились
- **AND** кандидаты перечислены в ADR-0002 как рекомендация с условием проверки лицензии

### Requirement: Конфликт с COSMIC разрешается в пользу COSMIC с пометкой MVP

Там, где решение COSMIC расходится с действующим контрактом Светлицы, проектный документ SHALL
фиксировать космическую версию как отправную с пометкой `MVP по COSMIC`, а позицию паритета MATE —
оставлять незакрытой в парити-листе. Отказ от космической версии SHALL оформляться ADR.

#### Scenario: Конфликт перечислен, а не размазан

- **WHEN** перенос выполнен
- **THEN** в ТЗ есть перечень конфликтов с указанием «как у нас / как у них / MVP сейчас»
- **AND** каждый конфликт имеет строку в парити-листе соответствующего компонента

#### Scenario: Пометка не выдаёт MVP за паритет

- **WHEN** позиция помечена `MVP по COSMIC`
- **THEN** в парити-листе она не может иметь статус «готово» как закрытие паритета MATE
