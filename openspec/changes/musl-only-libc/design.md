## Context

Контракт описывает glibc-систему с systemd как данность, а не как выбор:

| Где | Что сказано сейчас | Что требует ADR-0023 |
|---|---|---|
| ТЗ 3.1 | «системный пакетный Rust не используется», версия из rustup | пакетный Alpine-Rust, rustup в контейнере нет |
| ТЗ 23, 217 | ворота на bare metal Pop!_OS, `systemd-slice`, `MemoryMax=12G` | Docker на Alpine, лимит контейнера |
| ТЗ 272 (схема) | «Системные: PipeWire/WirePlumber, **logind**, PAM» | свой слой сидов поверх `seatd` |
| ТЗ 194 | DPMS → `power-profiles-daemon`/`systemd-inhibit` | свой слой, `systemd-inhibit` нет |
| ТЗ 681 | «релиз-зависимость от logind (fallback: прямой вызов systemctl)» | fallback = основной путь |
| ТЗ 793 | letopis v1: `/var/log` + `journalctl -o json` | v1 без системных журналов |
| ТЗ 833, 849 | logind: сон/hibernate/inhibit, `Lock`/`Unlock` | сигналы от `klyuchnik` |
| ТЗ 209 | `gettext-rs` (libc-локаль подразумевается) | запрет libc-локали, таблицы на Rust |
| ADR-0013 | «Docker-образ — отклонён ранее в пользу VM» | принят, с оговоркой о границах |

Что показала проверка (полный список источников — таблица «Проверено» в ADR-0023):

- **Код почти не мешает.** ni одного обращения к `libc::`, `nix::`, `dlopen`, `iconv`, `setlocale`,
  `strcoll`, `getpwuid` в `crates/` и `xtask/`; 41 пакет в `Cargo.lock`, `libc`/`nix` отсутствуют.
- **Мешает замыкание.** EFL 1.29.0 + Elementary, glib/gio, poppler, gstreamer, fontconfig/harfbuzz/
  fribidi, libheif/librsvg/libwebp, PipeWire, libinput/eudev/libdrm — всё это пересобирается под musl.
- **Alpine закрывает инфраструктуру, но не UI-стек.** В индексе (35 799 пакетов) есть openrc 0.63.2,
  busybox 1.38.0, seatd 0.9.3, weston 16.0.0, cage 0.3.1, rust/cargo/rustfmt/rust-clippy 1.100.0,
  cargo-deny 0.20.2, sccache 0.17.0, nodejs 24.22.3, meson, `ninja-build`, clang16/18, musl-dev 1.2.6,
  glib 2.90, poppler, mesa 26.3.1. Нет: `elementary` (EFL-тулкит), `efl` 1.29.0 (только 1.28.1 в
  `testing`), `font-pt-*`/`paratype`, `busybox-initscripts`.

## Decisions (решения владельца, 21.11.2026)

1. **Хост ворот — `192.168.0.80` (Gentoo). Q80 закрыт 21.11.2026** ответом владельца «на машине
   Gentoo». Проверено на ней: 16 ядер, 62 ГБ RAM (49 доступно), Docker 28.0.4. `.86` остаётся
   исключённой: 2.8 ГиБ свободно из 460 (ТЗ 3.8), чужая машина. **Роль macOS ответом не закрыта** —
   см. Q81: в ТЗ 3.8 и в ADR-0023 записано «не среда сборки», тогда как в том же ответе прозвучало
   «сборка на macOS»; противоречие правится только решением владельца, а не догадкой агента.
2. **Сиды — свой слой поверх `seatd`.** `elogind` (255.24-r2 в Alpine) отклонён: он дешевле кодом, но
   возвращает в образ `org.freedesktop.login1` — ту самую зависимость, от которой ТЗ 681 хочет
   избавиться. Граница слоя: `SvetlitsaSeat` (интерфейс крейта `svetlitsa-platform`) с реализациями
   `seatd` и `dummy` (для смоков). Реализация `logind` не заводится вовсе, чтобы её не «включили».
3. **`letopis` v1 без системных журналов.** Источник — журнал сеанса: `tracing`-слой каждого
   компонента пишет JSONL в каталог сеанса (`$XDG_STATE_HOME/svetlitsa/log/<сеанс>/`). letopis читает
   только его. Парсер syslog не пишется: формат не даёт структуры, а его поддержка — второй компонент
   вместо одного.
4. **Тулчейн — Alpine-Rust, тройка `x86_64-alpine-linux-musl`.** Следствие, которое надо принять
   явно: `rust-toolchain.toml` без rustup ничего не устанавливает, поэтому он переопределяется как
   «минимальная версия», а фактическая версия = версия из образа, зафиксированного digest'ом.
   `xtask ci --doctor` сравнивает `rustc --version` с пином и печатает digest образа.
5. **EFL/Elementary — из исходников под musl.** Наш `scripts/efl-build.sh` (уже существует для
   glibc-среды) переносится в контейнер и дополняется: `-Dnls=true` (в Alpine-пакете NLS выключен),
   тесты не глушатся (`!check` — чужое решение, мы его не наследуем), патчи — каталог `patches/efl/`.

## Решения, вытекающие из фактов (не вопросы владельцу)

- **Динамическая линковка musl.** Rust-таргет musl линкует CRT статически по умолчанию, а EFL грузит
  модули через `dlopen` (`src/lib/eina/eina_module.c`, 7 обращений). Статика + `dlopen` = нерабочие
  модули, поэтому в `.cargo/config.toml` закрепляется `crt-static = false` для musl-таргета, а
  `crt-static = true` остаётся исключением только для setuid-хелпера `stavni-auth` (ADR-0009).
- **Локаль и перекодирование — на Rust.** `strftime("%B")`, `strcoll`, `iconv` запрещены воротами:
  в musl нет данных локалей (`strftime` даст английские имена), сортировка пойдёт по кодовым точкам,
  набор `iconv` урезан. Русские имена месяцев/дней — `icu` или собственные таблицы, перекодирование
  — `encoding_rs` (windows-1251 есть).
- **Каталог пользователей — локальный.** `src/passwd/getpwent.c` в musl — это
  `fopen("/etc/passwd", "rbe")`, модулей NSS нет. sssd/ldap/winbind-пользователи для libc-поиска
  невидимы. Доменного пользователя тянуть нельзя — отдельный ADR, не «починим по ходу».
- **Скрипты — ash.** `xtask ci` проверяет `busybox sh -n scripts/*.sh`. Наш единственный скрипт
  (`scripts/fetch-vendor.sh`) близок к ash: башизм один — shebang `bash`; `python3` для разбора JSON
  меняется на `jq` (пакет есть), чтобы не тащить интерпретатор в контейнер ворот.
- **GNU-утилиты в контейнере допустимы, в образе — нет.** Сборочный контейнер ставит `coreutils`,
  `grep`, `findutils` (без них git/cargo работают хуже), но **наши** скрипты обязаны запускаться на
  ash/busybox, иначе проверка «образ без GNU» превращается в веру.

## Risks / Trade-offs

- **[Риск №1] musl-сборка EFL 1.29.0 + Elementary не собрана под musl никем.** Митигация: первая же
  задача секции 2 — прогон `efl-build.sh` в контейнере до любых правок ТЗ; план-Б (`efl` 1.28.1 из
  `testing`) держим как аварийный, но он не отменяет требования 1.29.0.
- **[Риск №2] Диска хоста не хватает.** Требование ТЗ 3.8 — ≥ 60 ГиБ, на `.80` свободно **19 ГиБ из
  206 (91%)**, в Docker формально освобождаемо 10.4 ГиБ (образы 15.6 ГБ, из них 66% reclaimable).
  Митигация: освобождение — действие владельца (чужие данные не трогаем), замер слоёв — задача 2.5,
  красные ворота от места — проблема среды, а не кода (3.8). Порядок — `docs/roadmap.md`, раздел 2.
- **[Риск №3] Свой слой сидов вместо logind = новый код в критическом пути** (сон, блокировка,
  пробуждение). Митигация: интерфейс тонкий (запрос сна, inhibitor, `Lock`/`Unlock`), реализация одна,
  смоки М2 проверяют «экран гаснет → движение мыши будит → `Lock` вешает сеанс».
- **[Риск №4] Диск хоста.** 19 ГиБ свободно при 91% занятом `/var/lib/docker`: слой с C-замыканием
  EFL занимает гигабайты. Митигация: многослойный `Dockerfile` с редкой сменой базового слоя,
  `docker system prune` в задаче обслуживания, замеры — в задаче применения.
- **[Риск №5] Отказ от systemd ломает не только logind.** Остаются `systemd-slice` (ТЗ 3.8),
  `systemd-inhibit` (194), `journalctl` (793), `systemctl` (681) — все четыре перечислены выше;
  ни один не должен остаться в тексте после правки.

## Open questions

- **Q81.** Что всё-таки имелось в виду под «сборка на macOS», если ТЗ 3.8 и ADR-0023 оставляют за
  macOS редактирование, исследование и документацию? Два чтения: (а) «сборка — не на macOS», тогда
  контракт верен и менять ничего не надо; (б) сборки действительно гоняются на Mac — тогда это
  пересмотр ADR-0023 с явной оговоркой, что Docker Desktop собирает `linux/amd64` через эмуляцию и
  скриншоты, RSS-прогоны и бенчи (10.3/10.5) на эмуляции не являются доказательством.
- **Q82.** Дисковый бюджет: освобождать 10 ГиБ на `.80` и искать там ещё 50, или поднимать вторую
  машину под правило подмены (ТЗ 3.8)?
