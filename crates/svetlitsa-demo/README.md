# Демо-клиент окон (`svetlitsa-demo`)

Тестовый артефакт: открывает окна, отвечает на запросы EWMH, ставит иконку в трей. Один крейт закрывает
две задачи — smoke-прогон трея (ТЗ 9.7) и RSS-сценарий «толоки» (ТЗ 10.5). Появляется в **М2**, вместе
с лавкой.

## Контракт для smoke-сценариев (менять — это ломать смоук)

| Что | Значение |
|---|---|
| `WM_CLASS` | `svetlitsa-demo` — по нему окно ищет `xdotool search --class`, без гонок по pid |
| Заголовок | `svetlitsa-demo:<роль>` — роль отличает окно друг от друга при N окнах |
| CLI | ровно под зафиксированные сценарии: `--windows N` (ТЗ 10.5), `--tray` (ТЗ 9.7). Флагов «на будущее» нет |
| Готовность | окно появляется после запуска процесса, исчезает по `SIGTERM` — сценарий ждёт окно поллингом, не `sleep` (ADR-0011) |

## Правила

- Не бинарь внутри `xtask`: `xtask` — инструмент ворот, его зависимости есть зависимости ворот; demo —
  тестируемый артефакт со своим циклом изменений.
- Живёт по тем же воротам (`clippy`, `test`, PR): его правка ломает смоук-сценарии всего проекта.
- Лицензия — `MIT OR Apache-2.0` по ADR-0002: связывается с `svetlitsa-ui`, кода MATE не содержит.
