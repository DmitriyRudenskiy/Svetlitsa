# 03 · Первый зелёный smoke-прогон: `xtask smoke` и право листа на `готово`

Статус: открыт — зависит от тикета 02 · Раунд 13 · ТЗ 6.9, ADR-0011, Q83

## Зачем он вообще появился

`smoke_proven()` в `xtask/src/main.rs` жёстко `false`. Пока так, ворота правильно не дают
листам статус `готово` и штамп `Закрыт` (Q83, тикет 04 раунда 12). Это единственная оставшаяся в метрике парити константа, зашитая в код вручную,
и снять её может только прогон, а не правка bool.

## Порядок (обратный желанию начать с кода)

1. Первый прогон — **вручную и по-человечески**: `xvfb-run`, `xdotool`, снимок, проверка,
   что окно живёт, вывод в журнал. Только после него становится ясно, что именно стоит
   автоматизировать.
2. `xtask smoke <крейт>` — обёртка над уже найденным сценарием, с кодом возврата и
   артефактами в `artifacts/`.
3. `smoke_proven()` читает результат прогона (отпечаток прогона в `artifacts/` или запись
   в каноне), а не литерал. Мутация, которую обязан поймать тест: «файла прогона нет →
   `готово` краснеет».

## Что запрещено

- Переворачивать `smoke_proven()` до появления артефакта прогона.
- Писать раннер раньше шага 1: сценарий без увиденного окна = «почти зелёное» (ADR-0006).

## Проверка

`cargo run -q -p xtask -- smoke <крейт>` зелёный · `cargo run -q -p xtask -- parity --check`
печатает nonzero `покрыто N/1338` и `функциями покрыто M/974` только там, где человек
поставил `готово` после этого прогона.
