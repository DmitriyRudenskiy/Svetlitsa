# Grill-аудит: метрика парити (раунд 12)

Дата: 2026-11-16. Проведён по `docs/superpowers/specs/2026-11-16-parity-metric-design.md`
(текст спеки на тот момент). Протокол: один вопрос за ход,
по одному следствию, решения регистрировались в реестр журнала (Q82…Q89). Формат ответа — из
ТЗ 11: решение до кода, откат, проверка.

## Аудит по секциям спеки

### 1. «1338 модулей»

**Наблюдение.** Печать `модулей .c: 1338` считает позиции карты ТЗ по листам. Уникальных
пар `каталог/файл` — 1233: три пары крейтов (`uzelok`/`uzelok-core`,
`kritskaya`/`kritskaya-core`, `barometr`/`svitok-plugins`) смотрят в одни C-каталоги,
плюс внутри одного листа один файл может быть назван дважды.
**Проверено:** `xtask parity --check` (старая строка), `grep -h '^  - \`' docs/parity/*.md | sort | uniq -d | wc -l` → 105.
**Решение:** Q82 (два числа) + Q84 (ключ `каталог/файл`).

### 2. «вердиктами покрыто 0»

**Наблюдение.** Ветка `covered` для открытых листов считается подстрокой по всему тексту
листа, но печать всегда нулевая, потому что покрытые позиции записываются в `covered`,
который обнуляется? — нет: `covered` для открытых листов не считается вовсе; в `by_sheet`
он есть, в печать идёт переменная закрытых листов.
**Следствие.** Метрика врёт в обе стороны: «0» при наличии вердиктов, «покрыто» при
отсутствии вердиктов (если бы печать использовала `by_sheet`).
**Решение:** Q83 (позиция закрыта ровно когда есть строка таблицы с статусом из легенды).

### 3. substring-покрытие: реальны ли коллизии

**Проверено:** `main.c` — в 18 листах 38 упоминаний; `gpm-common.c` — 5;
пара `acpi-plugin.c` / `ibm-acpi-plugin.c` в `barometr.md`.
**Решение:** Q86 (точное совпадение).

### 4. групповые вердикты

**Наблюдение.** Практика «одной строкой про четыре файла» уже есть в прозе листов.
**Решение:** Q84 — одна строка = один ключ; групповой вердикт раскрывается поимённо.
**Проверка:** тест «групповой вердикт не покрывает двух позиций».

### 5. `готово` до smoke

**Наблюдение.** Q48 уже требует smoke для `готово` (ТЗ 6.2), но легенда листов
(`docs/parity/README.md:31`) обещает `готово` без оговорки — два места против одного правила.
**Решение:** Q83 — до первого зелёного smoke только `нет`/`в работе`/`отложено`.
**Не исполнено в раунде 12:** smoke в среде ворот не запускается (`xtask ci --local`
печатает пропуск). Это названный пробел, а не разрешение.

### 6. функции публичной поверхности

**Наблюдение.** Раздел «Публичные функции» есть у шести листов (974 имени), в метрике его
нет; функция без модуля (`libmenu::menu_monitor_unref`) остаётся непокрытой.
**Решение:** Q87 — отдельный счёт, ключ `каталог::имя`, закрытие библиотечного листа
требует `M/M` поверхности.

### 7. одна дробь или две

**Аргумент за одну:** проще. **Аргумент против:** модуль и функция закрываются разными
критериями, одна дробь прятала бы непокрытую поверхность за покрытыми файлами.
**Решение:** Q87 — две дроби в одной строке.

### 8. «пустой статус» красить или нет

**Наблюдение.** 148 позиций traktir без статусов = красные ворота? Это не работа человека,
а её отсутствие; ворота краснеют до того, как человек сел за лист.
**Решение:** Q88 — черновик: не вердикт, не красным, строки предлагаются по `--draft`.
**Последствие для метрики:** покрытие не двигается черновиком; пока черновики есть, их
число печатается (позднее — Q91).

### 9. где живёт строка вердикта

**Наблюдение.** Вторая таблица/свой парсер = вторая система имён (запрет ТЗ 11).
**Решение:** Q88 (часть 2) — одна строка таблицы, один парсер `parse_rows`,
вёрстка `render_table`.

### 10. идемпотентность `--draft`

**Наблюдение.** Перегенерация уже обязана быть идемпотентной (Q47.1).
**Решение:** Q88 (часть 3) — повторный `--draft` не добавляет ни строки; проверяется
двумя прогонами на временном дереве и фактом прогона на реальном листе.
