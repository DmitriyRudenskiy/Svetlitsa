# 08 · Фичи парити-листа: второй уровень ТЗ 5.1 вне перечня и вне метрики

Статус: закрыт · Раунд 12 · ТЗ 5.1, 6.3 · Q93, Q86, Q49

## Конфликт, а не опечатка

ТЗ 5.1 и глоссарий требуют двух уровней: «модули и **фичи** — обязательно для всех
компонентов; пофункционально — только публичный API библиотек». `docs/parity/README.md`
показывал фичу строкой таблицы вердиктов:

```
| закладки, память истории | фича | в работе | MVP: smoke 9.17 |
```

С Q93 (`66e3d9e`) такая строка красна: ключ обязан быть позицией перечня, а фича перечнем
быть не может — генератор перечисляет модули `.c` из зеркала и публичные функции из
заголовков, фичу нельзя вывести из C-оригинала. Пример README противоречил правилу ворот,
которое те же ворота и печатают в тексте ошибки.

## Решение (не изобретение, а стыковка двух правил)

Фича — позиция того же листа, но **не позиция перечня**: она живёт списком рукописного
блока (`- закладки — MVP: smoke 9.17`), вердиктом таблицы не является и в покрытие не
входит — ровно как проза, которая вердиктом не считается уже сейчас (Q86, тест
`проза_вердиктом_не_считается`). Механического знаменателя у фичей нет: их перечень —
проектное решение (ТЗ 6.5, ADR-заготовка «какие фичи в итерации»), а не факт об оригинале,
и выводить его агенту нечем.

Тем самым таблица вердиктов = позиции перечня = метрика; фичи = объём итерации = список со
статусом и пометкой. Оба требования ТЗ 5.1 остаются в силе, ни одно правило ворот не
ослаблено.

## Что сделано

- `docs/parity/README.md`: пример таблицы без строки-фичи, блок «Фичи» показан списком,
  секция объясняет, почему фича не позиция.
- ТЗ 6.4 (5.1 в теле шага 1): формулировка, где живут фичи и почему они вне дроби.
- Глоссарий: термин «Фича (парити-листа)».
- Тест-страж `фичи_списком_не_становятся_вердиктами`: список фичей не создаёт строк
  вердикта, не двигает покрытие и не красит лист — если ворота когда-нибудь начнут
  разбирать списки, тест это заметит.

## Не исполнено (названо, а не сделано молча)

- **Ворота не требуют наличия блока «Фичи» в листе.** Требование «фичи обязательны для всех
  компонентов» по-прежнему держится только текстом ТЗ. Проверить его воротам нечем до тех
  пор, пока перечень фич — решение человека: требовать непустой блок значит получить 31
  красную строку и соблазн вписать туда что попало. Правильный вход — тот же, что у
  разбора `traktir`: блок пишет человек, ворота сверяют форму.
- **Пометка фичи (`MVP` / `v1` / `отложено`) не сверяется**: список — проза для ворот.
