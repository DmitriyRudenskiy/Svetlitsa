# 06 · Названные пробелы раунда 12: штамп на настоящем git и поле `Судьба:`

**Статус:** закрыт (`e6c0807` — поле `Судьба:`, `677d179` — обёртки git на настоящем
репозитории, следом документы). Тесты `xtask` 60 → 63 → 64, шесть мутаций пойманы,
ворота зелёные; в журнале — раунд 12, тикет 06.

**Что было зелёным и чем закрыто:** поле `Судьба:` разобрано и сверяется с перечнем (ключ —
позиция, половина строки красна, покрытие не двигает); обёртки git получили `*_in(dir, …)`,
негативный кейс предковости строится на одноразовом `git init -b main` с веткой `side`.

**Что делает система сегодня:** ворота сверяют штамп закрытия с git через три обёртки
(`commit_exists`, `ancestor_of_main`, `tag_commit`), но воробей-проверка `closing_problems`
подставляет им ответы руками — настоящие обёртки негативным кейсом не проверены, и «нет
предка main» мог бы печатать всегда-true код. Второе: ТЗ 6.3 обещает судьбу листа в поле
`Судьба:`, текст ошибки отправляет человека в это поле, а самого поля в коде нет — судьбе
негде легально жить, и человек возвращает её в столбец статуса.

**Goal:** обе дыры закрыты проверкой, а не обещанием: обёртки git вызываются на
одноразовом репозитории с реальной чужой веткой, `Судьба:` разбирается, валидируется и
покрытие не двигает.

## Как проверяется (верификационная цепочка)

1. **Настоящий git.** `git init -b main` во временном каталоге, коммит на `main`, коммит на
   `side`; `ancestor_of_main_in(main-sha)` истина, `ancestor_of_main_in(side-sha)` ложь,
   `commit_exists_in(несуществующего)` ложь, `tag_commit_in` возвращает закоммиченный sha;
   `closing_problems` на настоящих ответах красит штамп с чужим коммитом текстом
   «не предок main». Краснота шага — отказ компилироваться: обёртки не принимали дерево,
   негативный кейс было нечем выразить.
2. **`Судьба:`** — строка `Судьба: <ключ> — <текст>` в рукописном блоке. Красны: строка без
   ` — `, пустая сторона, ключ вне перечня листа (Q93). Не красна и **не покрывает**
   валидная судьба: покрытие двигает только таблица вердиктов.
3. Ворота целиком: `./target/debug/xtask ci --local`, мутации по две на каждое новое
   правило (журнал, Q53).
