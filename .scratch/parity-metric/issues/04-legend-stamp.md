# 04 — Легенды листов и ворота штампа закрытия (Q83, Q89)

**What to build:** Ни один лист не обещает `готово` в своей легенде статусов; все 31 лист
получают легенду, переписанную генератором, и ни один вердикт при этом не добавлен.
Объявить лист закрытым можно только валидным штампом (`main@<sha>`, предок `origin/main`,
существующий тег `canon-rN`), и закрытие требует зелёного smoke-прогона, которого у воробья
ещё не было — то есть сегодня объявить закрытым нельзя, и попытка красна текстом, а не
отсутствием проверки.

**Статус: закрыт** (коммиты `56dce01` · `dc63871` · `860dc30`; журнал — «Раунд 12, тикет 04»).

## Критерии приёмки

- [x] Легенда каждого листа переписана генератором в явном режиме (`xtask parity --legend`:
      «проставлено: 31 · уже было: 0», второй прогон — «проставлено: 0 · уже было: 31»).
- [x] `xtask parity --check` красен на листе, чья легенда обещает `готово` без зелёного
      smoke: отказ отдельным текстом, а не «нет статуса» (мутация «вернули в легенду» —
      8 красных тестов).
- [x] `xtask parity --check` красен на закрытии без smoke-прогона: даже с валидным sha
      («валидный sha — необходимое, но не достаточное условие»).
- [x] `xtask parity --check` красен на фейковом штампе закрытия: sha отсутствует в
      репозитории, не является предком `origin/main`, тег не существует, хвостового коммита
      нет; git-проверки параметризованы и тестированы инъекцией.
- [x] `xtask parity --check` красен, если лист закрыт, а вердикты не все проставлены
      (для функций — отдельным числом).
- [x] `xtask parity --check` красен, если статус позиции описывает судьбу листа
      («заменено конструкцией», «переносится полностью») вместо вердикта.
- [x] `xtask parity --check` красен, если статус позиции вообще не из легенды.
- [x] `xtask parity --check` красен, если позиция помечена `готово` до первого зелёного
      smoke-прогона листа.
- [x] Ни одного вердикта не добавлено: `покрыто 0/1338`, `функциями покрыто 0/974`,
      закрытых листов 0; в диффе листов — только блок легенды.
