# 04: Отыскание имени возвращает один из четырёх названных исходов

**Parent:** `.scratch/svetlitsa-icons/spec.md`

**What to build:** Разработчик компонента подаёт предикату имя и то, что есть в теме (тему передаёт
вызывающий — до диска крейт не дотрагивается), и получает один из четырёх названных исходов:
**отклик** (имя из списка, файл в теме есть — исход несёт непустой путь), **промах** (имя из списка,
файла в теме нет — исход несёт отсутствующее имя), **чужое имя** (имени нет в закрытом списке),
**калёное имя** (имя не проходит форму). Подмены похожим именем нет ни в одном исходе: ни один путь
не отдаёт чужое имя вместо запрошенного.

`image-missing` — именованное **имя-промах**, предписанное freedesktop-спекой и уже входящее в
закрытый список. Его запрашивает вызывающий, закрывая промах, и он же пишет об этом строку в журнал.
Предикат его не подставляет: верни он его сам — и промах стал бы неотличим от успеха, а логировать
стало бы нечего.

Лога внутри крейта нет: запись в журнал — побочный эффект, а предикат обязан остаться чистым.
Требование «строка в журнал» — контракт вызывающего кода, а не библиотеки. Повторный запрос
имени-промаха делается ровно один: нет его в теме — это второй промах, и третьего запроса не
происходит.

Демонстрируется фикстурной темой: прогон печатает все четыре исхода на четырёх запросах, и ни в одном
«отклике» не встречается пустой путь.

## Проверено

- `find(имя, тема) → Outcome::{Hit,Miss,Foreign,Malformed}` — слова глоссария те же: отклик,
  промах, чужое имя, калёное имя. Порядок проверок: форма → список → тема.
- Непустой путь — свойство типа: `IconPath` собирается только приватным `from_theme` внутри
  `find`; из-за пределов крейта отклик с пустым путём не построить.
- Промах несёт искомое имя (`document-properties`), а не `image-missing`; имя-промах доступен
  вызывающему как `IMAGE_MISSING` и **проверяется** на вхождение в закрытый список
  (`имя_промаха_доступно_вызывающему_и_лежит_в_списке`).
- Контракт вызывающего — `crates/svetlitsa-icons/tests/caller.rs` (видит только публичный API):
  строка журнала с исходным именем, ровно два обращения к теме (своё имя + `image-missing`),
  отсутствие имени-промаха даёт второй промах, а не цикл.
- Фикстурная тема, четыре запроса → четыре исхода, вывод прогона в `docs/journal.md`; пустого
  пути в отклике нет.
- Мутации: подмена `Miss { name: IMAGE_MISSING }` → 2 `FAILED`; `from_theme` без проверки →
  `FAILED`; обход формы → `FAILED`; обход списка → `FAILED`. Вывод — в журнале.
- Имя вне списка и имя испорченной формы не паникуют и не дают пустого пути: оба исхода
  останавливаются до обращения к теме (`asks == 0`).
- Новых строк в таблицу ТЗ 6.3 не добавлено: исходы отыскания — поведение API, канон шесть
  строк закрыт тикетами 01/02/03.
- `cargo test -q -p svetlitsa-icons` → `11 passed` + `3 passed`, `0 failed`;
  `cargo run -q -p xtask -- ci --local` — ворота зелёные.
