# Журнал «Светлицы»

Две функции: счётчик итераций контрольных точек (ТЗ 3.2, ADR-0004) и протокол решений, чтобы следующая
сессия не переспрашивала то, о чём уже договорились.

## Счётчик итераций контрольной точки М0

Итерация = один прогон `xtask ci` вместе с правками после него (глоссарий). Бюджет — 4. На четвёртом
неуспехе — стоп-лосс ADR (ТЗ 3.2).

| Итерация | Что проверяли | Итог |
|---|---|---|
| — | контрольная точка М0 ещё не запускалась | **заблокировано:** среда ворот не выделена (ТЗ 3.8, ADR-0003, вопрос «кому принадлежит 192.168.0.86 и можно ли освободить ≥ 60 ГБ») |

Ворота на macOS (`xtask ci`) прогонялись: `fmt`/`clippy`/`test`/`lints`/`licenses.csv` — зелёные,
`doctor` — красные по свободному месту. Это ожидаемо и означает «это не среда ворот» (ADR-0003), а не
«код сломан».

## Протокол решений (раунды 1–3 разбора ТЗ)

Формат: вопрос → решение. Проверенные факты помечены «проверено».

### Раунд 1
1. Статус ТЗ и репозиторий → ТЗ = контракт, монорепо в `/Users/user/Svetlitsa`, ADR и глоссарий пишутся по ходу.
2. Полнота карты репозиториев → **проверено: 46 репозиториев, 45 кодовых**; 15 неучтённых получили вердикты (ТЗ 2.1).
3. Среда разработки → сборочная машина `192.168.0.86` по ssh, macOS = редактор (детализировано в раундах 2–3).
4. FFI-стратегия → сокращение поверхности (Elementary+Edje+Efreet+Eet), bindgen для широких заголовков, контрольная точка М0 = 4 итерации (ADR-0004).
5. Событийный цикл → zbus в отдельном потоке, демоны без окон живут без Ecore (ADR-0005).
6. Wayland → 1.0 = сеанс поверх готового композитора, свой композитор — пост-1.0 (ADR-0007).
7. Лицензии → наследуются по upstream, CSV в репозитории (ADR-0002).
8. CI → ворота локальные `xtask ci`, workflow-файлов нет (ADR-0006).
9. Гранулярность парити → два уровня: модули/фичи для всех, функции — для публичного API библиотек (ТЗ 5.1).
10. Автономность → правило эскалации: четыре класса решений требуют вопроса (ТЗ 6.2).
11. Публикация → crates.io и имена не резервируются до 1.0 (ТЗ 12.10).
12. Доступность и i18n → 1.0 = клавиатура + контраст + анимации + шрифты, скринридеров нет, языки ru/en (ТЗ 7.3, 12.8–12.9).

### Раунд 2
13. Где живёт канон → (уточнён в раунде 3, см. 24).
14. Мощность машины → **проверено: bare metal Pop!_OS 24.04, 16 ядер, 46 ГБ RAM, 11 ГБ свободно, ~1 ГБ доступно RAM, Rust/EFL/meson отсутствуют** (ADR-0003).
15. Откуда EFL → релизные тарболы 1.29.0 в `/opt/svetlitsa-efl`, пин + sha256; apt даёт только 1.27 и без Elementary.
16. Git-поток → `origin` = голый репозиторий на машине сборки, рабочее дерево на Mac, `rsync`, sshfs запрещён.
17. Лицензионные поправки → **проверено по зеркалам:** mate-terminal/mate-netbook — GPL-3, mozo/libmateweather — LGPL-2.1, libmate-desktop/mate-menus/libcaja-extension — LGPL-2, caja — микс.
18. Судьба `wm-core` → крейт убран из 1.x, логика внутри `starshina` (ADR-0008).
19. Дыры таблицы 4.4 → +10 строк (DnD, буфер обмена, ComboBox, Stack, Paned, Viewport, редактируемые ячейки, IME, печать, AT-SPI), три ADR на DnD/буфер/IME.
20. Модель PAM → setuid-root хелпер `stavni-auth`, logind только как источник состояний (ADR-0009).
21. Фикстуры миграции → дампы с разовой машины MATE, скрипт + коммит текста (ТЗ 3.4).
22. Механика линтов → **проверено на cargo 1.97.1** (ADR-0010).
23. Что такое итерация → один прогон `xtask ci`, счётчик здесь (ТЗ 3.1).

### Раунд 3
24. Доступ к канону → вариант «в»: канон пересобирается на Mac из текста разговора; копия в песочнице остаётся непроверяемым ориентиром, а не источником истины.
25. Исправленная схема линтов → наследование без переопределений + allowlist; **проверено: `priority = -1` у `clippy.all` обязателен**.
26. Политика `vendor/mate` → shallow-клоны, `docs/licenses.csv` коммитится, ворота проверяют CSV, а не зеркала.
27. 60 ГБ на машине сборки → **открыто:** требует подтверждения владельца `192.168.0.86`.
28. MSRV → термин убран, инструмент пинится в `rust-toolchain.toml` (1.97.1), внешней политики до М5 нет.
29. Печать → вне 1.0 (береста, свиток), ТЗ 12.12.
30. Контуры проверки → итерация / закрытие компонента / ночная «толока» (ТЗ 10.3).
31. «Серая тема» → механическая провалка ворот в быстром контуре; пиксельные эталоны — в «толоке» после стабилизации «Лубка».
32. MVP → прогоняемый smoke-сценарий; «MVP готов» ≡ «smoke зелёный» (глоссарий, ТЗ 6.9).
33. Трей на Wayland → XEmbed невозможен в принципе, SNI возможен, панель зависит от layer-shell (ТЗ 9.7, 12.13).
