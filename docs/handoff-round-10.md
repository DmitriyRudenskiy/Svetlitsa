  список совпадает`.
- **Тест графа зависимостей (Q68)** — `svetlitsa-efl`, любой `*-sys`, появившийся `build.rs`

## Правила, за которые бьют (нарушалось в этом раунде)

- **Нумерация Q сквозная.** Раунд 10 завёл `Q1–Q15`, а `Q1–Q63` заняты раундами 1–9: ссылки
  вели на чужие решения, в том числе в комментариях `xtask`. Перед тем как сослаться на номер,
  посмотреть, кем он занят. Чинить — новым коммитом: предки подписанного тега не переписываются
  (сообщение `f8f949f` так и осталось со старыми номерами, и это правильно).
- **Пустой прогон — не доказательство (Q57).** Зелёный тест с нулём проверенных случаев
  (граф зависимостей на пустом манифесте) красится мутацией так же, как правило.
- **Множество не хранит обещания.** Повтор имени в листе схлопывался `BTreeSet` и показывался
  зелёным: ловит парсер входа, а не структура данных.
- Остальные в силе: число живёт со своей командой (Q61), мутация без `FAILED` — намерение (Q60),
  негатив обязан дать красное и зелёное в той же итерации (Q53), не прогнано сегодня — значит
  не проверено (Q57).

## Бытовое по этой машине (новое)

- `git verify-tag` в свежем клоне красен: `gpg.ssh.allowedSignersFile needs to be configured`.
  Нужно `git -c gpg.ssh.allowedSignersFile=canon/allowed_signers verify-tag canon-rN`;
  `xtask canon` передаёт файл из проверяемого дерева сам (секция «Проверка подписи канона»
  в README).
- `--follow-tags` толкает только аннотированные теги; `git ls-remote <remote> | grep canon-r10`
  покажет и объект тега, и `^{}` — сравнивать с `sha` из `canon.toml` нужно второе.
- Порядок закрытия раунда: закрывающий коммит → `git tag -s` → проверка дерева тега worktree'ом
  → коммит записи в `canon.toml` → ворота на коммите записи. Дерево не может содержать свой sha.
- `git commit --amend` безопасен на неопубликованном и непомеченном head; на предках канон-тега —
  нет (передвинул бы тег).
- Скан секретов `git grep -E 'ghp_|…'` теперь сам на себя натыкается: журнал перечисляет эти
  шаблоны. Читать хиты, а не только exit code.
- `cargo test -- фильтр1 фильтр2` фильтрует по обоим, но cargo останавливается на первом
  упавшем тестовом бинарнике: для «покраснело ли в двух крейтах» нужен `--no-fail-fast` или
  два прогона.
- Мутации держать скриптом с бэкапами в `/tmp` и восстановлением в цикле (правило раунда 9:
  никогда не `git checkout <файл>` поверх незакоммиченного).
