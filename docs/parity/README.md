# Парити-листы

Один файл на компонент: `<крейт>.md`, 31 лист — 28 по карте ТЗ 2 и 3 ядра по карте ТЗ 2.2.
Два уровня (ТЗ 5):

- **модули и фичи** — обязательно для всех компонентов;
- **пофункционально** — только публичный API библиотечных крейтов (`izba`, `traktir`, `vedro`,
  `bukvar`, `uzelok-core`, `ambar-core`, `svitok-core`).

## Функциональный слой = публичная поверхность (Q48)

Не «все C-функции репозитория», а контракт, который оригинал отдаёт наружу:

1. заголовки, которые билд-система объявила публичными (`install_headers` в meson,
   `*_HEADERS` в autotools); если билд-система ничего не перечисляет
   (`libmateweather`), берётся каталог без `*-private.h`, и заголовок раздела это говорит;
2. из текста вырезаются комментарии и export-макросы, собираются объявления
   нестатических функций; **многострочный прототип — одно объявление**;
3. не поверхность: `static`, макросы, `typedef`-ы, члены-указатели на функции.

У `uzelok-core` (engrampa) публичных заголовков нет вообще — C-прототипа поверхности не
существует, перечень ведётся руками.

## Нулевой лист (Q49)

Лист обязан быть **непротиворечивым**, а не «полным». Если перечнять нечего (модулей ноль),
в рукописном блоке обязательны два непустых поля — иначе это притворство, а не парити:

```
Причина: C-оригинал — обёртка сборки, кода нет; единственный артефакт — gschema-оверрайд.
Переносится: значения оверрайда как дефолты сеанса «Светлицы» — М5.
```

Ворота красны, если нулевой лист стоит без обоих полей.

## Два блока в листе (Q47)

- **Генерируемый** между `<!-- BEGIN GENERATOR -->` и `<!-- END GENERATOR -->`: отпечаток зеркала
  (`HEAD` shallow-клона), дерево модулей C-оригинала (один `.c` = один модуль; автотесты оригинала
  отфильтрованы) и публичные функции. Его перезаписывает `xtask parity [крейт]` — руками не править.
- **Рукописный** после `END GENERATOR`: вердикты. Генератор его не трогает; лист без границ блока
  перегенерацией не перетирается — это чужая правка, объединяется вручную.

| Позиция | Тип | Статус | Пометка |
|---|---|---|---|
| `src/caja-window.c` | модуль | нет | |
| закладки, память истории | фича | MVP | smoke 9.17 |
| `caja_window_new()` | функция | готово | только для библиотек |

Статусы: `нет` / `в работе` / `готово` / `отложено (причина)`. Позиция `MVP` помечает то, что обязан
пройти к закрытию компонента; «готово» для MVP-позиции означает зелёный smoke-сценарий (ТЗ 6.9), а не
мнение исполнителя.

## Закрытие листа (Q48, Q49)

Лист закрыт и вердиктами покрыт 100 %: каждая позиция имеет статус, каждая строка перечня —
вердикт, MVP-позиции — «готово». Закрытие монотонно: закрытый лист не «додумывается» задним
числом, назад он открывается только с причиной в рукописном блоке. Закрытие помечается штампом
в рукописном блоке — только по нему ворота понимают, что лист закрыт:

```
Закрыт: 2026-11-16, коммит порта `abc1234`
```

## Ворота (`xtask parity --check`, шаг `parity` в `xtask ci`)

Красны, если: позиции карты ТЗ 2/2.2 нет листа; отпечаток зеркала в листе не совпал с
фактическим (перегенерировать — `xtask parity`); лист правился вне генератора; лист закрыт,
но вердиктов не хватает; нулевой лист без «Причина:» / «Переносится:». Покрытие открытого
листа печатается числом и красным не является: вердикт — работа человека, генератор его не
додумывает.
