# Парити-листы

Один файл на компонент: `<крейт>.md`, 31 лист — 28 по карте ТЗ 2 и 3 ядра по карте ТЗ 2.2.
Два уровня (ТЗ 5):

- **модули и фичи** — обязательно для всех компонентов;
- **пофункционально** — только публичный API библиотечных крейтов (`izba`, `traktir`, `vedro`,
  `bukvar`, `uzelok-core`, `ambar-core`, `svitok-core`).

## Функциональный слой = публичная поверхность (Q48)

Не «все C-функции репозитория», а контракт, который оригинал отдаёт наружу:

1. заголовки, которые билд-система объявила публичными (`install_headers` в meson,
   `*_HEADERS` в autotools); если билд-система ничего не перечисляет
   (`libmateweather`), берётся каталог без `*-private.h`, и заголовок раздела это говорит;
2. из текста вырезаются комментарии и export-макросы, собираются объявления
   нестатических функций; **многострочный прототип — одно объявление**;
3. не поверхность: `static`, макросы, `typedef`-ы, члены-указатели на функции.

У `uzelok-core` (engrampa) публичных заголовков нет вообще — C-прототипа поверхности не
существует, перечень ведётся руками.

## Нулевой лист (Q49)

Лист обязан быть **непротиворечивым**, а не «полным». Если перечнять нечего (модулей ноль),
в рукописном блоке обязательны два непустых поля — иначе это притворство, а не парити:

```
Причина: C-оригинал — обёртка сборки, кода нет; единственный артефакт — gschema-оверрайд.
Переносится: значения оверрайда как дефолты сеанса «Светлицы» — М5.
```

Ворота красны, если нулевой лист стоит без обоих полей.

## Два блока в листе (Q47)

- **Генерируемый** между `<!-- BEGIN GENERATOR -->` и `<!-- END GENERATOR -->`: отпечаток зеркала
  (`HEAD` shallow-клона), дерево модулей C-оригинала (один `.c` = один модуль; автотесты оригинала
  отфильтрованы) и публичные функции. Его перезаписывает `xtask parity [крейт]` — руками не править.
- **Рукописный** после `END GENERATOR`: вердикты. Генератор его не трогает; лист без границ блока
  перегенерацией не перетирается — это чужая правка, объединяется вручную.

| Позиция | Тип | Статус | Пометка |
|---|---|---|---|
| `caja-desktop/caja-window.c` | модуль | нет | |
| `dialogs/gsm.c` | модуль | в работе | |
| закладки, память истории | фича | в работе | MVP: smoke 9.17 |
| `caja_window_new()` | функция | нет | только для библиотек |

Первый столбец — **ключ `каталог/файл`** из перечня генерируемого блока. Базовое имя ключом
не является: `main.c` в `skhodka` лежит в четырёх каталогах, `gpm-common.c` в `kerosinka` —
в четырёх (Q85). Одна строка может называть несколько ключей (групповой вердикт) — покрываются
ровно названные, а один ключ не может иметь два разных статуса (Q84).

**Ключ строки обязан быть позицией перечня этого листа** (Q93). Ворота сверяют его точным
совпадением с перечнем и краснят строку, если позиции с таким ключом в листе нет: опечатка,
переезд файла в другой каталог, переименованная или ставшая статической функция. Лист с
таким вердиктом даёт «вердикт есть, покрытия нет» — то есть неотличим от строки, которую
человек ещё не писал. Черновик `--draft` сверяется наравне с вердиктом: перечень сдвинулся —
устаревшая строка красна, а не молчит. Ключи функций (`каталог::имя`) сверяются с
генерируемым разделом «Функции»: у листа, у которого функционального слоя нет вовсе, такая
строка красна всегда, а у листа с руками ведённой поверхностью список функций пишет человек,
и проверять ворота нечем.

## Легенда статусов (Q83)

Легенда живёт в рукописном блоке **каждого** листа — включая листы с нулём позиций — и
выглядит так:

```
Статусы позиции: `нет` / `в работе` / `отложено (причина)`; `готово` — только после первого
зелёного smoke-прогона листа (ТЗ 6.9, Q83), до него этот статус красен. `отложено` без
причины — не статус. Судьба листа — поле `Судьба:`, а не статус позиции.
```

Правила, которые из неё следуют и которые держат ворота:

- **До первого зелёного smoke — только `нет` / `в работе` / `отложено (причина)`.**
  `готово` красен: он означает прогнавшуюся сборку (ТЗ 6.9), а не мнение исполнителя, а
  smoke-сценарии в среде ворот не исполняются — прикрываться статусом нечем.
- **`отложено` без причины — невалидный статус.** Причина внутри статуса, а не в пометке:
  отложенное обязано быть перечислимым (ТЗ 5).
- **Судьба листа — не статус.** «заменено конструкцией», «переносится полностью», «не
  переносится» — поле `Судьба:` рукописного блока; в столбце статуса это красный статус
  вне легенды.
- **Статус вне легенды красен; легенды в листе не быть не может** — её отсутствие красное,
  как и статус не из списка. Поддержать легенду во всех листах — `xtask parity --legend`:
  команды без флага рукописный блок не трогают (Q47.1), а там, где легенда правилась
  руками, команда останавливается и просит человека.
- **Лист без позиций не вранье** (Q49): `Позиций: 0` обязан иметь «Причина:» и
  «Переносится:», а дроби покрытия печатаются как `нет позиций`, а не как `0/0` (Q79).

## Судьба листа (Q83)

Судьба — не готовность позиции, а решение о переносе. Она живёт в рукописном блоке,
по строке на позицию:

```
Судьба: `libmenu/editmenu.c` — заменено конструкцией `MenuTree`
```

- **Поле ничего не покрывает.** Готовность позиции двигает только таблица вердиктов: иначе
  «заменено конструкцией» закрывала бы позицию без вердикта человека (Q47).
- **Ключ обязан быть позицией перечня** — тем же правилом, что и вердикт (Q93): опечатка в
  имени файла красна, а не живёт в листе зелёной подсказкой.
- **Половина строки красна.** `Судьба: <ключ>` без ` — ` и без текста — незаполненное поле,
  а не разобранный лист.

## Метрика ворот (Q82, Q86, Q87)

Покрытие считает **только строки таблицы вердиктов**: точное совпадение ключа и непустой
статус из легенды. Ни подстрока, ни упоминание в прозе вердиктом не являются — вердикт по
`ibm-acpi-plugin.c` не покрывает позицию `acpi-plugin.c`, а фраза «Причина: `main.c` …»
не покрывает `main.c`. Пары таких имён в листах есть и сегодня — 12 листов и 30 позиций
(команда и полный список — журнал, раунд 12); вот одна из них:

```console
$ grep -o '`[a-z-]*acpi-plugin\.c`' docs/parity/barometr.md | sort -u
`acpi-plugin.c`
`ibm-acpi-plugin.c`
```

Вердикт по длинному имени закрыл бы короткое — на старой метрике это выглядело бы как
покрытие.

Шаг печатает разные числа — они выводятся вот так (`cargo run -q -p xtask -- ci --local`):

```
parity: листов 31/31 · позиций: 1338 · уникальных каталог/файл: 1233 · покрыто 0/1338 · функциями покрыто 0/974 · закрыто 0 · открыто 31
```

Позиций больше, чем уникальных файлов: один upstream-каталог разбирают два крейта
(`uzelok` и `uzelok-core` смотрят в `engrampa`). Ноль знаменателя — красный цвет, а не
зелёное `0/0` (Q79).

**Две дроби, а не одна (Q87).** `покрыто N/1338` — модули перечня; `функциями покрыто N/974`
— публичные C-функции библиотечных листов: `izba` 243, `svitok-core` 323, `traktir` 142,
`vedro` 122, `bukvar` 74, `ambar-core` 70. Складывать их в одно число нельзя: у модуля и
у функции разные критерии закрытия, и одна дробь прятала бы непокрытую поверхность за
покрытыми файлами. Ключ функции — `каталог::имя` (`libmenu::menu_layout_node_new`): функция
принадлежит библиотеке, а не каталогу `.c`. Лист библиотеки не закрывается, пока поверхность
не покрыта `M/M`; у 25 листов публичной поверхности нет — их ноль печатается как ноль,
а не как покрытие.

## Черновик строк вердикта (`xtask parity --draft <крейт>`, Q88)

Заполнять таблицу вердиктов — работа человека, но переписывать позиции перечня в таблицу
руками — работа без смысла. По **явному** флагу генератор предлагает строки-скелет для
позиций без вердикта — модули, затем функции публичной поверхности:

```console
$ cargo run -q -p xtask -- parity --draft traktir
parity: листов перегенерировано: 1
parity (--draft traktir): строк добавлено: 148 · статус пустой: вердикт пишет человек (Q88)

| Позиция | Тип | Статус | Пометка |
|---|---|---|---|
| `libmenu/desktop-entries.c` | модуль |  | подсказка: статус из легенды |
| `libmenu/entry-directories.c` | модуль |  | подсказка: статус из легенды |
…
| `libmenu::menu_verbose` | функция |  | подсказка: статус из легенды |
```

Свойства, за которые ворота держат тестами и мутациями:

- **Молча — ни одной строки.** Без флага поведение прежнее: перегенерация трогает только
  генерируемый блок (Q47.1), даже если таблица вердиктов пуста.
- **Идемпотентность.** Повторный прогон не добавляет ни строки: под ключом, где строка уже
  есть (вердикт, черновик или строка с битым статусом), второй строки не появляется.
  Два прогона `--draft` подряд дают тот же файл.
- **Пустой статус — не вердикт.** Черновик не двигает покрытие и не красным: человек до
  строки ещё не дошёл, и красной строкой это не лечится. Пока черновики есть, шаг печатает
  их числом: `… покрыто 0/1338 · функциями покрыто 0/974 · черновиков: 148 · закрыто 0 …`
  (число исчезает, когда черновиков нет — это список дел, а не вердикт).
- **Заполненное не трогается.** Строки со статусом и проза рукописного блока («Причина: …»)
  остаются байт в байт.

## Закрытие листа (Q48, Q49, Q89)

Лист закрыт и вердиктами покрыт 100 %: каждая позиция имеет статус, каждая строка перечня —
вердикт, MVP-позиции — «готово». Закрытие монотонно: закрытый лист не «додумывается» задним
числом, назад он открывается только с причиной в рукописном блоке.

Закрытие помечается **штампом в рукописном блоке** — только по нему ворота понимают, что лист
закрыт. Формат: дата, коммит ветки `main`, и — если закрытие совпало с релизным тегом — сам
тег:

```
Закрыт: <ГГГГ-ММ-ДД>, main@<sha>
Закрыт: <ГГГГ-ММ-ДД>, main@<sha> · canon-rN
```

Что ворота проверяют по штампу (Q89):

1. формат — дата и `main@<sha>`; штампа `abc1234` и прочих примеров в листьях быть не
   должно, подглядеть настоящий sha можно командами из раздела «Ворота»;
2. коммит существует: `git cat-file -e <sha>^{commit}`;
3. коммит — предок `main`: `git merge-base --is-ancestor <sha> main`;
4. если приписан `canon-rN` — тег существует и указывает ровно на этот коммит
   (`git rev-parse --verify --end-of-options canon-rN^{commit}` peel == sha);
5. **валидный sha — необходимое, не достаточное условие**: закрытие требует зелёного
   smoke-прогона листа (ТЗ 6.9). Пока smoke в среде ворот не исполняется, любой штамп
   «Закрыт:» красен независимо от sha — это названный пробел среды, а не разрешение
   закрывать на слово.

## Ворота (`xtask parity --check`, шаг `parity` в `xtask ci`)

Красны, если: позиции карты ТЗ 2/2.2 нет листа; отпечаток зеркала в листе не совпал с
фактическим (перегенерировать — `xtask parity`); лист правился вне генератора; лист закрыт,
но вердиктов не хватает; нулевой лист без «Причина:» / «Переносится:»; строка вердикта без
ключа или со статусом вне легенды (пустой статус — черновик `--draft`, он не вердикт и не
красным, Q88); в листе нет легенды статусов или в ней обещано `готово` без smoke (Q83);
`отложено` без причины (Q83); `готово` до первого зелёного smoke (Q83); штамп «Закрыт»
битый, ссылается на несуществующий или чужой коммит или приписал несуществующий `canon-rN` (Q89);
у одного ключа два разных статуса; в дереве нет ни одной
позиции перечня. Покрытие открытого листа печатается дробью и красным не является: вердикт —
работа человека, генератор его не додумывает.
