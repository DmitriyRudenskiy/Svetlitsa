# ADR — журнал решений

Сюда попадают только решения «почему», а не «как». Порядок: контекст → решение → следствия;
решение, у которого нет следствий, — не решение, а заметка. Контракт объёма и майлстоунов —
[`../../TASK.md`](../../TASK.md), здесь объясняется выбор, из которого контракт состоит.

**Как пересматривать.** Новый ADR не правит старый молча: в старом появляется строка статуса со
ссылкой на нового владельца решения, а текст старого остаётся — по нему читается, почему тогда
решили именно так. Пересмотр без ссылки на причину («передумали») считается незакрытым решением.

## Два правила, которые проверяются воротами, а не памятью

**1. Зависимость появляется вместе с задачей.** Никаких `cargo add` «на будущее» и «может
пригодиться в М4»: зависимость заводится той же итерацией, что и задача под неё, и в той же итерации
получает строку в [`../licenses.csv`](../licenses.csv) (тип лицензии, upstream, версия, способ
подключения). Ветка без строки в CSV — красные ворота `xtask ci --licenses`, и это не придирка
ревьюера: `docs/licenses.csv` — единственный источник, по которому релиз отвечает на вопрос «что
мы распространяем». Кандидаты из разборов (в том числе семь крейтов из COSMIC) зависимостями не
считаются, пока под них не открыта задача.

**2. Одна FFI-привязка на подсистему.** На подсистему — ровно один способ ходить в C: D-Bus →
`zbus`, GLib-ядро → `glib`/`gio` FFI, сеть → `NetworkManager` D-Bus, звук → `libpipewire` **или**
сокет `pipewire-pulse` (выбор фиксируется ADR-0022 до первой строки микшера), Wayland-протоколы →
`wayland-client`/smithay, X11 — нет вовсе (ADR-0016). Второй способ той же заботы — это два набора
багов и две проверки там, где пользователь видит одну. Правило живёт в ТЗ 3.3 и в
[`deny.toml`](../../deny.toml): запрещённые крейты (`x11rb`, `x11`, `xcb`, `libpulse-binding`,
`gtk`) ловятся воротами, а не договорённостью.

## Как писать новый ADR

1. Файл `ADR-NNNN-краткое-имя.md` (нумерация сквозная, свободных номеров не оставляем).
2. Шапка: `Дата: … · Статус: … · <номер раунда/задачи, QNN, ссылка на ТЗ>`.
3. Контекст — только проверяемые факты, с датой наблюдения; если факт не переснят, он так и помечается.
4. Решение — одной фразой в начале абзаца, дальше детали. Следствия — что становится невозможно.
5. Альтернативы и почему отклонены (если отклонять было нечего, ADR обычно не про решение, а про наблюдение).
