# ADR-0005: Исполнитель zbus — в отдельном потоке; демоны без окон живут вообще без Ecore

Дата: 2026-11-15 · Статус: принято · Решение раунда 1 (Q5), ТЗ 3.5/4.3

## Контекст
Первая редакция ТЗ утверждала: «tokio не вводится, асинхронность живёт на цикле Ecore и zbus». У zbus
собственный async-исполнитель, и «жить на цикле Ecore» он не может без явного интеграционного слоя. Это
была недоопределённость, а не решение.

## Решение
Исполнитель zbus живёт в **отдельном потоке**. В главный (Ecore) поток события приходят через **один**
публичный примитив переноса из `svetlitsa-efl` (обёртка над `ecore_main_loop_thread_safe_call`).
Демоны без окон (`domovoy`, `kerosinka`) не поднимают Ecore вообще. `tokio` в workspace не вводится.

## Последствия
- Правило для ревью: прямых `async`-вызовов из UI-кода нет, блокирующего I/O на Ecore-потоке нет.
- Один примитив переноса вместо «обёртки, где удобно» — иначе гонки появятся в 28 компонентах.
- Минус: два потока в компоненте вместо одного; цена — предсказуемость вместо «плывущих» зависаний.
