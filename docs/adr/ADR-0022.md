# ADR-0022: Звук — только PipeWire; клиентский слой один

Дата: 2026-11-21 · Статус: принято · Решение владельца (21.11.2026), ТЗ 3.3, 9.15, ADR-0002

## Контекст

Контракт планировал обратное (ТЗ 9.15): «v1 — PulseAudio-совместимый слой, v2 — PipeWire через
pipewire-FFI», а в белом списке ТЗ 3.3 висела строка `libpulse` с планом ухода «нет —
PulseAudio/WirePlumber остаётся». Две ветки микшера и два FFI-слоя — это ровно то, что называется
максимумом зависимостей, и держим мы их ради стека, который «Светлица» использовать не собирается.

## Решение

**Звуковой стек проекта — только PipeWire (`pipewire` + `WirePlumber`). PulseAudio как самостоятельный
стек не поддерживается.** Клиентский слой один:

- **v1 «Граммофона» сразу на PipeWire**, PulseAudio-ветки микшера нет (ТЗ 9.15 переворачивается).
- **Привязка одна, а не две.** Зрелого pure-Rust клиента PipeWire нет, поэтому «минимум
  зависимостей» означает «одна FFI-привязка», а не «ноль C». Выбор между `libpipewire` и
  pulse-совместимым сокетом `pipewire-pulse` — задача 6.11, а не решение по месту в коде.
- **Уровни по приложениям даёт pulse-совместимый протокол PipeWire.** Отказ от него в пользу
  `pw-protocol` теряет функцию (регулировка громкости по приложениям), а не зависимость, — поэтому
  он не считается «облегчением».
- **Принцип шире звука:** зависимость появляется с задачей, проверкой `LICENSE` конкретной версии и
  записью в `docs/licenses.csv`; расширение белого списка ТЗ 3.3 — только через ADR (ADR-0002).

## Последствия

- **PulseAudio-стек — ограничение, а не ошибка пользователя:** строка в ТЗ 12.x, компонент сообщает
  причину прямо, а не показывает нулевую громкость.
- **Ворота проверяют «один слой»:** одновременное присутствие `libpulse`- и `libpipewire`-привязки
  красит `xtask ci` (задача 3.8).
- **Правятся четыре места ТЗ:** 3.3 (строка `libpulse`), 4.2 (схема «Системные: PulseAudio, logind,
  PAM»), 9.15 (граммофон), 12.x (ограничение), плюс описание стека в README и разделе 1.
