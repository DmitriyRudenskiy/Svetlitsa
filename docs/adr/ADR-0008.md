# ADR-0008: Крейт `wm-core` удалён из 1.x; логика WM живёт внутри `starshina`

Дата: 2026-11-15 · Статус: принято · Решение раунда 2 (Q18), ТЗ 4.2/9.28

## Контекст
`wm-core` задумывался как общий слой логики WM (фокус, привязки, рабочие столы) для `starshina` (X11) и
будущего композитора (Wayland). После ADR-0007 второго потребителя в 1.x нет.

**Уточнение 2026-11-21 (ADR-0016, ADR-0019).** Пары «X11-менеджер / Wayland-композитор» больше нет
вовсе: `starshina` — и то, и другое, и единственный композитор проекта. Основание удалить `wm-core`
не ослабло, а усилилось: расщеплять логику окон между двумя платформами нечего.

## Решение
Крейт `wm-core` из дерева 1.x убран. Логика фокуса/привязок живёт внутри `starshina` за внутренними
трейтами. При старте пост-1.0 композитора она выносится в `wm-core` отдельным ADR. Требование
«проектировать starshina с расчётом на wm-core» из М2 снято.

## Последствия
- Плюс: нет крейт-спекуляции с одним потребителем; нет «правильного» API, спроектированного вслепую.
- Минус: вынос логики потом дороже, чем сейчас. Осознанно: цена вымышленного API выше.
