# smoke — delta

## ADDED Requirements

### Requirement: Первый прогон — руками, раннер — только после него

Первый smoke-прогон SHALL выполняться вручную (`xvfb-run`, `xdotool`, снимок) с записью в
`docs/journal.md` до появления `xtask smoke`: автоматизировать можно только увиденное окно
(ADR-0006).

#### Scenario: Прогон задокументирован

- **WHEN** в `docs/journal.md` есть запись прогона со снимком и описанием окна
- **THEN** раннер обязан покрывать этот сценарий, а не изобретать новый

#### Scenario: Раннер раньше прогона

- **WHEN** `xtask smoke` написан до записи прогона в журнале
- **THEN** работа считается «почти зелёной» и не закрывает тикет 03

### Requirement: Контракт `xtask smoke <крейт>`

`xtask smoke <крейт>` SHALL возвращать 0 только когда окно крейта появилось под Xvfb,
в `artifacts/` лёг непустой снимок, а процесс завершился без ошибки; ненулевой код —
без артефакта успеха.

#### Scenario: Зелёный прогон

- **WHEN** `xtask smoke svetlitsa-icons` завершается кодом 0
- **THEN** в `artifacts/` лежат снимок и отпечаток прогона

#### Scenario: Окно не встало

- **WHEN** окно не появилось за отведённое время
- **THEN** код возврата ненулевой, отпечаток прогона не записан, `xtask ci --smoke-only`
  красен на этом шаге

### Requirement: `smoke_proven()` читает прогон, а не литерал

`smoke_proven()` SHALL читать отпечаток прогона (`artifacts/` или запись канона); правка
`bool` не является прогоном (Q83). Тест-страж обязан краснеть на возврат константы `true`.

#### Scenario: Мутация — константа

- **WHEN** `smoke_proven()` возвращает `true` без артефакта прогона
- **THEN** тест-страж красен, а вердикты `готово` на листах — красным по Q83

#### Scenario: Артефакт есть

- **WHEN** отпечаток зелёного прогона листа лежит в `artifacts/`
- **THEN** `готово` этого листа не окрашивается по причине smoke; остальное решает метрика

### Requirement: Контрольная точка М0 в составе smoke

Прогон контрольной точки М0 SHALL включать окно Elementary из `svetlitsa-ui`, Edje-макет
темы, адаптер `Vec<T>` → Genlist item class, Eo-колбэк, приехавший в главный поток, и
скриншот под Xvfb. Бюджет — 4 итерации (ТЗ 3.1), счётчик — в `docs/journal.md`.

#### Scenario: Бюджет исчерпан

- **WHEN** четвёртая итерация контрольной точки неуспешна
- **THEN** работы останавливаются и оформляется стоп-лосс ADR с планом Б (ТЗ 3.2);
  «ещё одна попытка» без ADR запрещена
