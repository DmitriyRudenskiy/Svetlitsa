# parity-metric

## Purpose

Метрика `xtask parity` и вердикты парити-листов: считать только то, что посчитано, и называть
каждое число тем, чем оно является (Q82–Q93). Формат листа и легенда статуса — в
`docs/parity/README.md`; регистр решений и раунды — в `docs/journal.md`; здесь — только
нормативные требования к поведению ворот.

## Requirements

### Requirement: Метрика печатает разные числа

Метрика SHALL печатать отдельные числа: позиции по листам и уникальные пары
`каталог/файл`; покрытое не превышает
свой знаменатель; ноль позиций — красное состояние. Слово «модуль» как единица счёта запрещено,
единицы — «Позиция» и «Вердикт» (глоссарий).

#### Scenario: Один каталог разбирают два крейта

- **WHEN** одна пара `каталог/файл` встречается в листах двух крейтов
- **THEN** печатаются оба числа: `позиций: 1338 · уникальных каталог/файл: 1233`,
  и ни одно не подписано чужим именем

### Requirement: Вердикт — строка таблицы с легальным ключом

Позиция SHALL считаться закрытой ровно когда в таблице вердиктов есть строка с ключом
`каталог/файл` и статусом
из легенды. Совпадение подстрокой и упоминание имени в прозе — не вердикт (Q86). Ключ обязан
быть позицией перечня этого же листа (Q93); групповой вердикт обязан раскрываться поимённо (Q84).

#### Scenario: Имя файла упомянуто в прозе

- **WHEN** `main.c` встречается в тексте листа вне таблицы вердиктов
- **THEN** позиция `main.c` остаётся непокрытой

#### Scenario: Вердикт несуществующей позиции

- **WHEN** строка вердикта ссылается на ключ, которого нет в перечне листа
- **THEN** ворота красны: «вердикт есть, покрытия нет» неотличимо от ненаписанной строки,
  поэтому молчать зелёным ему запрещено

### Requirement: Черновик — не вердикт

Строки с пустым статусом MUST NOT попадают в покрытие; печатаются отдельным числом;
`xtask parity
--draft <крейт>` идемпотентен и вставляет скелет по явному флагу (Q88, Q90–Q92).

#### Scenario: Повторный прогон --draft

- **WHEN** `--draft` запущен второй раз без изменений листа
- **THEN** добавлено 0 строк, число черновиков не изменилось, `diff` пуст

### Requirement: Публичная поверхность считается своим счётом

Функции раздела «Публичные функции» SHALL покрываться отдельным знаменателем; лист библиотеки
не закрывается, пока его поверхность не покрыта полностью (Q87).

#### Scenario: Модуль готов, API не разобран

- **WHEN** все модули листа закрыты, а функции покрыты не все
- **THEN** лист не закрыт, и метрика показывает `функциями покрыто M/974`

### Requirement: Пометка позиции и право листа закрываться

Четвёртый столбец (`MVP` / `v1` / `отложено`) SHALL сверяться воротами; вердикт без пометки
красен; закрытие листа требует `готово` на каждой MVP-позиции (ТЗ 6.4). Статус `готово`
возможен только после первого зелёного smoke-прогона листа (Q83).

#### Scenario: Закрытие до первого smoke

- **WHEN** лист пытаются закрыть, а `smoke_proven()` — false
- **THEN** ни одна MVP-позиция не может нести `готово`, закрытие красное

### Requirement: Штамп закрытия сверяется с настоящим git

Поле `Судьба:` SHALL разбираться и сверяться с перечнем; штамп `Закрыт` SHALL проверяться
вызовом
настоящего git на одноразовом репозитории, а не своей реализацией «похожего» (Q89, тикет 06).

#### Scenario: Чужая ветка в тестовом репозитории

- **WHEN** тестовый репозиторий содержит метку времени и HEAD не там, где штамп
- **THEN** сверка штампа это видит и краснеет

### Requirement: Фичи — второй уровень, вне дроби

Рукописный блок «Фичи» MUST NOT быть позицией перечня, вердиктом и входащим в дробь покрытия
(Q86); наличие блока воротами не требуется.

#### Scenario: Строка фичи попала в таблицу вердиктов

- **WHEN** имя из блока «Фичи» стоит ключом вердикта
- **THEN** ворота красны: фича выводится не из оригинала, а из решения человека (ТЗ 5.1)
