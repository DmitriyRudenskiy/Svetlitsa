# Метрика парити, которой можно верить (раунд 12)

**Дата:** 2026-11-16 · **Тикеты:** `.scratch/parity-metric/issues/01…05` · **Реестр:** Q82–Q92 в `docs/journal.md`

> Файл восстановлен из контекста сессии после того, как рабочую копию спеки и
> `grill.md` потеряло (артефакт не дожил до коммита). Содержание — как на момент
> grill-аудита; правки, внесённые по ходу раунда, перечислены в конце и не
> переписывают первоначальные формулировки.

## Проблема (что наблюдали, а не что хочется починить)

Шаг `parity` печатал:

```
parity: листов 31/31 · модулей .c: 1338 · вердиктами покрыто 0 · закрыто 0 · открыто 31
```

Три дефекта в одной строке:

1. **1338 — это не файлы.** Это позиции карты ТЗ, перечисленные по листам. Один
   upstream-каталог могут разбирать два крейта: `uzelok` и `uzelok-core` смотрят в
   `engrampa`, `kritskaya` и `kritskaya-core` — в `libgdata`, `barometr` и
   `svitok-plugins` — в `applet`. Ровно поэтому позиций 1338, а уникальных пар
   `каталог/файл` — 1233. Печатали одно, называли другое (`модулей .c`).
2. **«Покрыто» не означало «есть вердикт».** Ветка `if !s.status.is_empty() { covered += 1 }`
   считала только закрытый лист; для открытого «покрыто» было числом совпадений **подстрокой**
   по всему тексту листа. Ни один лист не закрыт, поэтому печать всегда выдавала `покрыто 0`,
   и метрика молчала о том, что вердиктов никто не писал.
3. **Метрика не видит публичные C-функции.** У шести библиотечных листов есть раздел
   «Публичные функции» (в дереве 974 имени: `svitok-core` 323, `izba` 243, `traktir` 142,
   `vedro` 122, `bukvar` 74, `ambar-core` 70), в метрике их нет. Модуль «готово» — а
   поверхность библиотеки не разобрана.

## Решения (зарегистрированы Q82–Q89; полный текст — журнал, раунд 12)

| ID | Решение |
|---|---|
| Q82 | Метрика печатает разные числа: `позиций` (позиции по листам) и `уникальных каталог/файл`; покрытое знаменатель не превышает; ноль позиций — красное состояние |
| Q83 | Позиция закрыта ровно когда в таблице вердиктов есть строка с этим ключом и статусом из легенды; статус `готово` возможен только после первого зелёного smoke-прогона листа |
| Q84 | Ключ позиции — `каталог/файл`; дубль ключа в дереве легален и требует вердикта по каждому вхождению; групповой вердикт раскрывается поимённо, одна строка таблицы = один ключ |
| Q85 | Термины «Позиция» и «Вердикт» — в глоссарий; в метрике есть только они, слово «модуль» как единица счёта запрещено |
| Q86 | Имя в прозе листа — не вердикт; ключ сверяется точным совпадением |
| Q87 | Функции публичной поверхности считаются своим счётом; лист библиотеки не закрывается, пока его поверхность не покрыта полностью |
| Q88 | Таблица вердиктов с пустым статусом считается черновиком: не вердикт и не красная строка. Строки-скелет вставляет `xtask parity --draft <крейт>` по яв­ному флагу, повтор прогона идемпотентен |

## Объём раунда

**Входит:**

1. Метрика и её печать (тикеты 01, 02) — `xtask/src/main.rs`, тесты `xtask`.
2. Черновик строк вердикта по яв­ному флагу, одна реализация таблицы (тикет 03).
3. Легенда статуса (запрет `готово` до smoke, Q83) и ворота штампа закрытия (Q89) —
   текстовые ворота + тесты (тикет 04).
4. Разбор листа `traktir`: вердикты человека по позициям М1, **без закрытия листа** (тикет 05).
5. Документы: ТЗ 5 и 6.2 (метрика), глоссарий (`Позиция`, `Вердикт` — с отсылкой к журналу,
   не пересказ), `docs/parity/README.md` (что считается вердиктом), `CHANGELOG.md`.

**Не входит (реестр «не исполнено», а не «сделано»):**

- Закрытие `traktir` и любого другого листа — до первого зелёного smoke (Q83).
- Строка smoke в воротах: `xtask ci` не исполняет smoke-сценарии в этом окружении
  (нет `XDG_RUNTIME_DIR`). **Это названный пробел раунда, а не аргумент, чтобы оставить
  пробел в правилах.**
- Метрика по EFL-сигнатурам (`xtask api`) — отдельный фронтьер.
- Разбор остальных 30 листов, правки в `vendor/`, вторая парсится таблица, второй формат
  строки вердикта — в этом раунде ничего из этого не появляется.

## Как проверяем (воробей-таблица ТЗ 6.3, обязательна)

Правило: метрика парити не считает подстроку и прозу.

| Слой | Проверка |
|---|---|
| Тест | `xtask`: ключ позиции совпадает точным совпадением; подстрока длинного имени не покрывает короткий ключ; «Причина: `main.c` …» не покрывает `main.c`; групповой вердикт не покрывает двух позиций; функции считаются отдельно; пустой статус не вердикт; функции библиотечного листа попадают в метрику; лист без раздела «Функции» даёт ноль и не закрывается без покрытия функций |
| Мутация | сверка `contains` вместо точного совпадения; functions-раздел исключён из парсинга; пустой статус засчитан как вердикт; `готово` засчитан без smoke |
| Прогон | `xtask parity --check` до и после правки (вывод в журнал и CHANGELOG), `xtask ci --local` |
| Ожидаемый провал | мутация обязана уронить тест; тест, который мутация не трогает, правило не защищает |

## Проверка фактами (исполнено в раунде, команды и вывод — журнал раунда 12)

| Утверждение | Команда | Что должно быть видно |
|---|---|---|
| 1338 и 1233 — разные числа | `cargo run -q -p xtask -- parity --check` | `позиций: 1338 · уникальных каталог/файл: 1233` |
| дубли ключей реальны | `grep -h '^  - \`' docs/parity/*.md \| sort \| uniq -d \| wc -l` | 105 пар `каталог/файл` встречаются в двух листах |
| имена с подстрокой реальны | `grep -l 'ibm-acpi-plugin\.c' docs/parity/*.md` | `barometr.md`: вердикт по `ibm-acpi-plugin.c` не покрывает `acpi-plugin.c` |
| `main.c` в прозе — не вердикт | `grep -c '\`main\.c\`' docs/parity/*.md \| grep -v ':0'` | `main.c` упоминается в листах вне таблицы вердиктов |
| функции в листах есть | `grep -c '^[A-Za-z_][A-Za-z0-9_ ]*\*\?**[ ]*[a-z_][a-z0-9_]*(' docs/parity/izba.md` | десятки строк раздела «Публичные функции» |
| ни один лист не закрыт | `grep -l '^\*\*Закрыт\|Закрыт:' docs/parity/*.md` | пусто (запрет закрытий раунда 12) |

## Правки по ходу раунда (не переписывают решения выше)

1. **Q90–Q92, тикет 03.** Черновик = модули и функции публичной поверхности (Q90);
   пока черновиков больше нуля, шаг печатает их числом третьим числом (Q91); статус
   черновика остаётся пустым с текстом-подсказкой в пометке, отдельного флага `--all`
   нет (Q92). Отдельного маркера черновика не завели: пустой статус между третьей и
   четвёртой вертикалью и есть черновик.
2. **`traktir` — 6 модулей + 142 функции = 148 позиций**, а не «шесть модулей» и не
   «шесть позиций». Формулировка объёма тикета 05 и журнала исправлена на честное число:
   человеческая поверхность листа — 148 позиций.
3. **Идемпотентность — факт прогоном, не только мутацией.** В журнале записаны два
   прогона `--draft` подряд: второй добавляет 0 строк, `черновиков: 148`, статусы
   не тронуты, `diff` пустой.
4. **Операционный guard мутационного цикла.** Старт только с чистого закоммиченного
   дерева (`git status --porcelain` пуст), база — названный sha, откат —
   `git restore --source=<base-sha> -- <paths>` и `git diff --exit-code <base-sha>` после
   него. `git checkout -- <path>` с некоммиченными правками запрещён: он восстанавливает
   из index/HEAD и стирает работу (в этом раунде так потеряло три теста и половину
   CHANGELOG; восстановлено из снапшота).
5. **Q93, между тикетами 04 и 05.** Ключ строки вердикта (и черновика) обязан быть
   позицией перечня этого листа: `вердикт есть, покрытия нет` был зелёным и неотличимым
   от ненаписанной строки. Правило — в ТЗ 6.3 и `docs/parity/README.md`, тестов 56 → 60,
   мутаций пойма́но четыре.
6. **Guard из п. 4 нарушен снова** (тот же раунд, позже): мутационный цикл запустили с
   некоммиченным правилом, откат стёр его и четыре теста. Отсортировано не доверием к
   памяти, а порядком: сначала коммит, потом первая мутация — иначе цикл не запускается.
