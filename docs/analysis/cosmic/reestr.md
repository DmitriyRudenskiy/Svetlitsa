# Реестр разбора COSMIC DE

Контракт Светлицы — MATE (карта ТЗ 2, `docs/parity/`). COSMIC — **не контракт**, а источник
готовых Rust-решений. Поэтому это не парити-лист: здесь нет позиций «готово/в работе», есть вердикт
о переносимости. Порядок разбора и правила — `openspec/changes/cosmic-de-analysis/design.md`.

Вердикт (закрытый список): `переносим` — берём идею или контракт поведения; `добавляем` — берём
как готовую зависимость; `не переносим` — конфликтует со стеком или ADR; `мимо` — к Светлице не
относится. Уровень: `контракт` / `крейт` / `содержимое` / `—`.

Лицензионный гейт = список `allow` в `deny.toml` (MIT, Apache-2.0, BSD-2/3, ISC, Zlib, **MPL-2.0**,
LGPL-2.0/2.1, GPL-2/3), а не «только разрешительные»: проект уже принимает MPL-2.0 и GPL. Для
вердикта `добавляем` читается `license` из `Cargo.toml` самого крейта, а не из README репозитория.

Зеркала: `idea/<репозиторий>` (`--depth 1 --single-branch --no-tags`), в git не входят. `HEAD` —
голова зеркала на момент вердикта. Размер — `du -sh` зеркала с `.git`.

## Слой 2 — D-Bus/zbus-обёртки

Общее по слою, и оно же — причина, по которой ни один из этих крейтов не получает `добавляем`:
актуальный `zbus` на crates.io — **6.5.0** (rust 1.89), а космические обёртки сидят на **3.7/3.8**
(2023 год) или на git-версии. Это три мажора; переносится не код, а контракт — какие методы и
сигналы зовутся и в какие структуры раскладываются ответы. Наш `svetlitsa-dbus` по ТЗ 4.3 и
ADR-0005 — zbus без tokio-цикла в UI-потоке, то есть чужой async-код нам и не нужен.

## Чего в COSMIC нет — шесть компонентов Светлицы без космического аналога

Проверялось по двум независимым спискам: 136 пакетов оверлея (`idea/cosmic-overlay`, категории
`cosmic-base`/`cosmic-extra`/`cosmic-utils`) и 345 репозиториев org `pop-os` (GitHub API). Ни в одном
из них нет пакета, который был бы портом аналога ниже. Это не «мы не нашли», а «аналога нет»:
писать эти шесть компонентов придётся без референса, и правка «у COSMIC это уже сделано» к ним
неприменима.

| Компонент Светлицы | Upstream MATE | Космический аналог | Чем закрываться |
|---|---|---|---|
| `svitok` | atril | **нет** — `cosmic-viewer` читает только растровые картинки: в зависимостях `viewer-core` есть `turbojpeg`, `libheif-rs`, `resvg`, `zune-image`, но нет ни poppler, ни djvulibre | Только своя обвязка над poppler-rs/djvulibre (ТЗ 9.10), референса нет |
| `schoty` | mate-calc | **нет** — единственное упоминание арифметики в COSMIC это плагин `calc` у `pop-launcher` (строка 24), то есть строка ввода в поиске, а не приложение | Порт по upstream C-коду, сверять не с чем |
| `uzelok` | engrampa | **нет отдельного приложения** — архивы открывает сам файловый менеджер: `cosmic-files/src/archive.rs` на `tar`/`flate2`/`bzip2` | Либо повторять их путь (архив как ещё одна «папка» в амбаре), либо порт отдельным окном по ТЗ 9.12 — это решение объёма, а не техники |

| `bukvar` | libmatekbd | **частично** — `pop-os/xkb-data` (строка 3) покрывает перечисление раскладок и вариантов из `/usr/share/X11/xkb` | Единственный из шести, где готовый кирпич уже есть и он под MPL-2.0 |
| `barometr` | mate-sensors-applet | **частично** — `pop-os/sysfs-class` (устарел, 2021) и `cosmic-monitor` (он же про дозор, строка 48) | Кирпичи: `sysinfo` (MIT) для процессора/памяти/дисков; для датчиков — `/sys/class/hwmon` напрямую, как и решено в ТЗ 9.24 |

Побочно из того же списка оверлея: в `cosmic-utils` живут **13 сторонних апплетов**, которых нет в
карте ТЗ 2 и которые поэтому не разбирались: `cosmic-ext-classic-menu` (классическое меню запуска —
ближайший к нашей лавке по духе, но сторонний, не pop-os), `cosmic-ext-applet-clipboard-manager` и
`clippy-land` (история буфера — в MATE такой задачи нет вовсе), `cosmic-ext-applet-sysinfo`,
`cosmic-ext-calendar`, `cosmic-ext-storage`, `cosmic-ext-connect` (KDE Connect), `caffeine`,
`gamemode-status`, `privacy-indicator`, `external-monitor`, а также отдельные приложения `examine`
(сведения о системе), `tweaks` (расширенные настройки) и `accounts` (онлайн-аккаунты). Ни одно из
них не входит в 28 компонентов, поэтому в реестр не попало — но это готовый список того, что
сообщество дорастивает на панель сверх дефолта, и он полезен при разговоре о объёме самоделок.
